# Assumptions and open questions

Status: living record, last updated 2026-11-05 after the slice 0 probes (design draft v4). It collects every scored assumption from synthesis v1 to v3, the original plan, the two design candidates and the v3 review. Verified facts are not scored. Verified lines cite the probe id and the results file in `probes/results/`. Rows that a probe settled left the table, and their numbers stay unused. Scores run from 1 to 10. A score below 7 means the item needs a probe before you build on it.

## Verified, not scored

- `enabledPlugins` precedence: the highest-precedence source that mentions a plugin id wins (Claude Code docs, page plugins/loading). Live probe `a-enabledplugins-precedence` confirms that a project `true` beats a user `false` (A31, `probes/results/claude.json`). The no-fetch check for a plugin that is not installed is still open (needs an operator).
- Codex `AGENTS.md` has no import syntax.
- OpenSpec 1.5.0 command paths for Claude Code and Codex, its telemetry payload (command name, version, surface, anonymous id, IP off) and its opt-out variables.
- The example restrictive plugin's hooks, and that it ships `package.json` without a lockfile.
- pstack 0.15.36 has no hooks and no `package.json`.
- The Claude Code Agent tool takes an `effort` parameter. Its `model` parameter accepts aliases only.
- Claude aliases resolved to full ids in subagent transcripts (`message.model`), with no alias-remap variable set.
- Codex `~/.codex/agents/*.toml` role files and the `[agents]` defaults (Codex source, via documentation search).
- omp `modelRoles` keys (`task`, `advisor`, `judge`, `plan`, `default`) and the `:effort` suffix.
- Headless flags. Claude: `claude -p --output-format`. omp: `omp -p`, `--mode text|json|rpc`, `--model`. Cursor: `cursor-agent -p --output-format json|stream-json`, `--model 'x[effort=high]'`, `--mode plan|ask`, `--list-models`, `--plugin-dir`, `--trust`, `--workspace`.
- Claude Code transcripts repeat a message's usage on each content block. Subagent usage lives in separate files.
- Cursor skill, rule, agent, plugin and hook locations, from Cursor documentation and a local layout survey.
- Always-on text on one machine: 25,346 bytes on Claude Code. One prompt hook injects 16,698 bytes per discovery prompt in an indexed repository and 0 bytes elsewhere, into the user message.
- omp user instructions file is `<agent dir>/AGENTS.md`, which is `~/.omp/agent/AGENTS.md` by default. omp passes it verbatim, so marker lines reach the model. `~/.codex/AGENTS.md` is not read (A2, probe `g-omp-agents-md-path`, `probes/results/omp.json`).
- Codex hides a skill from its listing through `agents/openai.yaml` with `policy.allow_implicit_invocation: false`. `$name` still invokes it. Codex ignores `disable-model-invocation` (A12, probe `f-codex-skill-hiding`, `probes/results/cursor-codex.json`). Tested on repo `.agents/skills` only.
- omp collapses duplicate skills by `SKILL.md` bytes plus frontmatter. A sidecar file such as `agents/openai.yaml` does not break the collapse. Differing copies get a `<provider>/<name>` entry (A13, probe `e-omp-skill-dirs-dedupe`, `probes/results/omp.json`).
- omp reads user skills from `<agent dir>/skills` and `~/.agents/skills`, and project skills from `.claude`, `.codex`, `.agents` and `.omp`. It does not read `~/.claude/skills` or `~/.codex/skills`. A bare command file in `<agent dir>/commands` works in `-p` mode (probe `e-omp-skill-dirs-dedupe`, `probes/results/omp.json`).
- Cursor collapses a skill by name, even when the bytes differ. The first source wins: `.cursor`, then `.claude`, then `.agents` or `.codex`. A23 is refuted as stated. Project directories only, model-reported (probe `b-cursor-dedupe`, `probes/results/cursor-codex.json`).
- Cursor `--plugin-dir` loads plugin skills. `disable-model-invocation` removes a skill from Cursor's list, and `/name` still invokes it. Project rules with `alwaysApply: true` load in `cursor-agent -p` (probe `j-cursor-plugin-rules`, `probes/results/cursor-codex.json`).
- `omp config set` rewrites `config.yml`. It drops comment lines and marker lines. It keeps unknown keys, key order, file mode and `modelRoles` values, and it creates an empty `config.yml.lock`. Read-only commands and `omp -p` do not rewrite (A26, probe `c-omp-config-rewrite`, `probes/results/omp.json`).
- The Codex `AGENTS.md` cap is 32,768 bytes. The cut falls between byte 32,714 and byte 32,800, and `project_doc_max_bytes` raises it (A32, probe `d-codex-agents-md-limit`, `probes/results/cursor-codex.json`).
- Claude Code `SessionEnd` fires in `claude -p` mode with no trust step. The payload has six string keys: `cwd`, `hook_event_name`, `prompt_id`, `reason`, `session_id`, `transcript_path`. `reason` was `other` for a `-p` run (A34, Claude part, probe `h-sessionend-payload`, `probes/results/claude.json`).
- Codex `exec`, Cursor and omp headless flags, and the omp rule that `omp -p` needs a closed stdin (probes `i-*-headless-flags`, `probes/results/*.json`).

## Open questions for the user

1. **Core membership.** The small core in decision 0005, or the larger set from design candidate 1 (mode skill, principle leaves, writing skills)? Do language-specific skills belong in the overlay?
2. **CVE without a cache.** On the first offline apply, should `cve` block (current draft) or warn?
3. **Public release.** When does the repository go public, and which vendored packs ship in it?
4. **First vendored pack.** cursor-team-kit or gstack `office-hours`?
5. **Binary name.** `rig`, or `rigctl` to avoid the Homebrew `rig` clash?
6. **Budget severities.** Confirm the proposed rule in decision 0012: block where the harness truncates, warn where text costs money.
7. **Codex pstack channel.** Keep unpinned copies in `~/.agents/skills`, vendor a generated tree for Codex, or skip pstack in Codex?
8. **Hybrid scope.** Is `hybrid` "hidden machine-wide, invocable in the listed projects", or something else?
9. **Cost source.** Where a harness records no cost, should rig compute cost from tokens and a price table that it maintains, or report tokens only?
10. **Alias retirement.** When does the `/pm` alias go: on a date, or when `rig stats` shows no use for a set period?

Machine-level questions (user-scope plugin flags, stale caches, account actions) are tracked outside this repository.

# Upstreams: pstack, gstack, cursor/plugins, superpowers, OpenSpec

Status: research record, 2026-11-04. Line references are pinned to these versions: pstack 0.15.36, gstack `b244e6d` (VERSION 1.95.5.0), cursor/plugins `bb68f236`, superpowers 7.0.0, OpenSpec 1.5.0. Read-only explorers produced the facts, and an orchestrator spot-checked them.

## pstack (MIT, Cursor plugin, Claude Code tree generated)

### Anatomy

- 58 skills, 2 agents, 23 playbooks under `skills/poteto-mode/playbooks/`, 24 `principle-*` leaves. About 2,437 SKILL.md lines plus 527 playbook lines. 7.0 MB in total.
- The native target is Cursor. The Claude Code tree is generated by `scripts/generate-pstack-harness-trees.mjs` in cursor/plugins. Claude Code support is one prose adapter, `docs/harness/claude-code.md` (67 lines). The model reads it each session. It maps Cursor tool names, model slugs and paths. The repository has no Codex or omp adapter.
- Playbooks cover task types (feature, bug-fix, investigation, refactoring, perf-issue and others) and operations (babysit, shipping, autopilot, opening-a-pr and others).
- Every code playbook ends with the "Opening a PR" playbook. Other chains exist, for example autopilot to babysit to shipping. `multi-phase-plan.md` hard-codes `pstack/skills/...` paths.

### Generator pattern (worth copying)

`scripts/generate-pstack-harness-trees.mjs` in cursor/plugins, 188 lines:

- One source tree, one `render()`, and `--check` that byte-diffs the output, exec bit included (`:118-152`).
- A TERMS table of 22 regexes for harness-specific tokens (`:28-51`). The generator fails if the adapter document has no row for a term that a skill uses (`:100-102`).
- A name lint (`:91-97`), link rewrite and a dangling-link check (`:106-165`).

### Progressive disclosure

- 57 of 58 skills set `disable-model-invocation: true`. Only `setup-pstack` is visible, at 275 listing characters.
- `poteto-mode/SKILL.md` (152 lines) holds an inline principle index (`:41-82`) and reads leaves by path. The rule "cite only leaves you read" pins this.
- Playbooks cite principles by slug only. So principles can stay in a core that is independent of any playbook.
- Under a foreign playbook nothing tells the model to read the leaves. A frame must state the verify and sequence invariants itself.

### Routing, context and caching

- Routing is prose only. `poteto-mode/SKILL.md:98-104` sets the defaults. Match the model to the job. The budget sets the start effort. Raise one step for the hardest work and lower one step for routine work. Use fast mode only when urgent. Change effort or speed, never the model family. Follow a fallback chain for rejected slugs.
- `setup-pstack` maps budgets to effort: unlimited to max, large to xhigh, medium to high, small to medium. It writes 17 role lines and panels as lists. The adapter maps slugs to model plus effort.
- The arena skill takes its cross-judge from another model family (`arena:30`).
- Gaps: no code enforcement, no token measurement, no prompt-cache awareness (a search finds none).
- Copy into rig: one line per role with a budget header, the effort ladder, panels as lists, the "never change family" rule, the cross-judge rule, summaries back from subagents, the TSV decision trail.

### Couplings

- Cursor-only features: the Subagents section (Task, `run_in_background`, cloud agents), Bugbot in 13 files, Automations in 6, `~/.cursor` paths in eval, session-pickup and worktree-cleanup.
- Dangling references to cursor-team-kit skills: `deslop`, `control-ui`, `control-cli`, `create-skill` (`README.md:263-267`).
- Hard-coded model slugs (`grok-4.7` 30 times, `claude-opus` 21 times). The `pstack-models` rule overrides them.
- `poteto-mode` appears in about 228 places, plus the `pstack:` prefix. A rename needs a global find and replace. Removing a skill is easy.
- No CHANGELOG. Frequent patch releases. A vendored copy would drift, so rig keeps pstack as an external pin.

## gstack (MIT)

### Anatomy

- 66 `SKILL.md.tmpl` templates, `scripts/gen-skill-docs.ts` (1,222 lines) and `scripts/resolvers/*.ts` render per host. Output is about 30,438 lines from 18,765 template lines, because the preamble goes into every skill.
- Needs Bun. About 200 bin scripts. State in `~/.gstack`. Opt-in telemetry. An hourly update check.
- About 1,485 `gstack` references in templates: paths, bin prefix, `GSTACK_*` variables, question IDs, update URLs.
- `NOTICE.md:130-152` credits pstack, and gstack bundles `licenses/MIT-pstack.txt`. The two packs share lineage.

### Preamble

`scripts/resolvers/preamble.ts:90-109` composes 19 pieces in tiers 1 to 4 by a `minTier` table (`:93-127`). The parts worth keeping as about 60 lines of plain markdown: ask-user format (one decision, a recommendation, options), completeness, confusion protocol, claims need evidence, completion status (DONE, BLOCKED, NEEDS_CONTEXT), search before building, voice and writing style. When AskUserQuestion is missing, the template falls back to `Q<N>` and `D<N>` prose (`SKILL.md.tmpl:373`).

### Multi-host configuration

`hosts/index.ts:24` lists 13 hosts, without omp or pi. `HostConfig` (`scripts/host-config.ts:38-138`) holds identity, capabilities, paths, a frontmatter allowlist, skip lists, path and tool rewrites, and install steps. Worth copying: a per-host record with rewrites, capabilities and a skip list. Too heavy for rig: 13 hosts, tiers, the Bun build chain.

### Routing, context and caching

- Per-host `defaultModel` (`scripts/host-config.ts:49`) only selects which model overlay goes in at generation. `model-overlays/<model>.md` (11 files, 180 B to 2 KB) enters through the preamble. A newer point release falls back to the generic overlay (`scripts/models.ts:68-98`).
- Code-enforced model policy for cross-model review: tiers `frontier` (plan review) and `smart` (implementation) in `lib/model-policy.ts` and `lib/model-catalog.ts`. Precedence: flag, then environment, then configuration pin, then catalog. `bin/gstack-models` reports the value and its source. A CI job checks catalog freshness.
- Review effort tiers per role are in code (`docs/model-policy.md:208-225`). The `/codex` skill caches a model probe for one hour and prints a token readout. xhigh costs about 23 times the tokens of high (gstack measurement).
- Context: v1.15.0.0 cut plan reviews from about 50 KB to about 30 KB. `preamble-hoist.ts` moves byte-identical sections into one shared `sections/preamble.md`, read once per session. `SKILL_BYTE_CEILING = 160,000` bytes, about 40,000 tokens, enforced by the generator (`gen-skill-docs.ts:1077`) and CI. A size ledger, a per-skill token bill (`gstack-context-bill`) and `/ship --token-cap` exist.
- Prompt caching: no code. Static generated files and the hoisted preamble help by accident. Lazy mid-session section reads and different overlay text per skill hurt.
- Copy: fallback to a generic overlay, tiered policy with an inspector, effort tiers by role, byte ceiling, size ledger, hoisting of byte-identical text only. Avoid: prose-only overlays, catalogs without a freshness check.

## superpowers and OpenSpec as providers

**superpowers 7.0.0.** A SessionStart hook injects `using-superpowers` ("1% chance ... MUST invoke", invoke before you clarify or explore). `brainstorming` has a HARD-GATE and a forced handoff to `writing-plans`. The execution skills keep their own ledger, require a worktree and set their own model tiers. It works only as a bundle with the hook suppressed. Narrow parts can fill step-slots: `verification-before-completion` (verify), `requesting-code-review` and `receiving-code-review` (code-review), `finishing-a-development-branch` (ship), `using-git-worktrees` (workspace).

**OpenSpec 1.5.0.** A CLI. Phases: explore (no code), propose (specify, design, plan), apply (implement), sync and archive (ship). It has no verify or review phase. Artifact paths come from CLI JSON (`resolvedOutputPath`), so a provider must call the CLI. Mild mandates and no session hijack. `openspec init --tools claude,codex,pi` writes `.claude/commands/opsx/*.md` (verified in `dist/.../adapters/claude.js`) and global `~/.codex/prompts/openspec-*.md`. The Claude skills-delivery path was not found in `dist`. `--tools` has no omp value. Telemetry is on by default. The configuration stores `telemetry.noticeSeen` and `anonymousId`. Opt-out is `OPENSPEC_TELEMETRY=0` or `DO_NOT_TRACK=1` (verified in `dist/telemetry/index.js`). Endpoint: `https://edge.openspec.dev`.

## Writing and anti-slop chain

A PR description today loads about 526 lines over three skills: writing-en 63, stop-slop 62 plus phrases 128 plus structures 134, asd-ste100 139.

The skills conflict on four points. Hedges: unslop and humanizer cut them, STE keeps modality. Em dashes: humanizer replaces them with colons, unslop restricts colons. Voice: humanizer adds it, writing-en forbids it. Quotes: unslop wants straight quotes, Polish rules want Polish quotes.

Proposed chain for rig:

- English: one merged `writing-en` (plain-language rules, pstack `technical-writing` layers, the pstack `unslop` catalog, stop-slop `phrases.md` and `structures.md` as references).
- Polish: `writing-pl` plus `humanizer-pl`.
- Agent-facing text: `asd-ste100` Strict mode plus `ste-lint.py`.
- Specs: the phrase pass of the merged `writing-en`.
- Code: `deslop`.
- Drop: English humanizer, and STE-flavored mode for PRs and docs.

Expected PR path: about 526 lines down to about 250. License notes: all MIT. `humanizer-pl` ships only `NOTICE.txt`, so add the upstream humanizer LICENSE. `asd-ste100` must never include the ASD dictionary.

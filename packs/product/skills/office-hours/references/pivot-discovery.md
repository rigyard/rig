# Phase 2C: discovery and pivot

Use this phase when the reality check finds no real outcome, the goal is a pivot, or the founder changes direction. A builder blocked on implementation stays in builder mode.

## Pivot flow

Ask each question separately. Wait for the answer before the next question.

1. Identify the concern. Does nobody value the product, or is the market too small?
   - For market size, estimate reachable buyers multiplied by a defensible annual price. Compare that ceiling with the founder's goal. Use incumbent revenue only when a source supports it. Label guessed inputs. The assignment tests the least credible input.
   - For lack of demand, use the discovery flow on the proposed direction.
2. Ask what the founder would work on if starting from zero today. Treat prior work as an idea source.
3. Ask whether the founder would leave their best current customer for the new direction. If they hesitate, say the decision remains open.
4. Discuss customer relationships and the possible loss of existing revenue. Do not assume that customer loss is acceptable.
5. Ask what result, by what date, would show the new direction is wrong. Record the agreed test in the memo.
6. Check whether other candidate directions remain unresolved before recording a settled decision.

## Discovery flow

Use the steps that match the evidence. Do not treat this list as a fixed questionnaire.

- With no customer conversations, agree a conversation count and a time window.
- With conversations but no usage, give the smallest usable version to one named person. More interviews do not test usage.
- With usage but no payment, test a specific price. The founder sends the payment request. This skill does not contact customers.
- Ask whether this is a major problem or an optional improvement. Treat polite interest as weak evidence.
- Ask one open question and listen. Use a rough demo when it can test an assumption.
- For a build, define one user and one workflow. Include simple cases first and name what waits.
- Consider manual delivery before automation. Identify what each delivery would teach.

Agree the count, date and result with the founder. Do not invent commitments or present example numbers as decisions.

## Memo-session routing

Keep Phase 3. Skip the landscape search and the second opinion in Phases 2.75 and 3.5.

In Phase 4, propose 2-3 candidate actions. Examples include customer conversations, a payment test, manual delivery or a small build. Use the alternatives format and wait for approval.

Phase 5 writes a one-page decision memo to `docs/memos/<slug>.md`. If this branch already has an approved memo whose action is a build, write a minimal design doc for that build instead.
